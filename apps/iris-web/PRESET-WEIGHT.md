# message-preset 瘦身 —— 设计输入

一个会话里第一个楼层 frame 要下载 **2.29 MB**（`message-preset.js`）。它有内容哈希、
走我们自己的源、强缓存，所以只付一次——但那一次是「打开一个带界面的聊天有多慢」的
主要项。

`WINDOWING.md` 把它记成了另一本账。这份文档是那本账。

**这是设计输入不是规格**：给出成分、语料使用面、瘦身选项与各自的破坏面。

日期 2026-09-02。

## 口径

- 标 **[产物]** 的来自 `npm run build:sandbox` 后的 `public/sandbox/`，可复跑。
- 标 **[语料]** 的来自 19 张真实角色卡。
- 标 **[上游]** 的来自 JS-Slash-Runner 4.9.1 检出。

---

## 一、最要紧的先说：**17.5% 是重复的字节**

[产物] `message-preset-*.js` 里的 FontAwesome 字体，**三个字重各被内联了两次**：

```
sha1 前缀      次数   每次       合计
e39fe840ea      2    208,559    417,118
0c2056bd90      2    157,159    314,318
3c6bbed1ca      2     33,879     67,758
1cf9caa053      1      6,415      6,415
                          ────────────
              实际占用    805,609 B
              去重后      406,012 B
              可省        399,597 B   ← 整包的 17.5%
```

成因在 `vite.message-preset.config.ts` 自己的注释里已经点到一半：**`all.min.css` 会在
几个子表里重复声明同一个 `@font-face`**。当时处理的是 `.ttf` 回退（那一轮把 5.49 MB
降到现在的量级），但**同一份 woff2 被多个 `@font-face` 各内联一次这件事没有被消除**。

**破坏面：零。**同一份字节的两个副本，删掉一份不改变任何行为——不是取舍，是修 bug。

**这一条应当先做，且和后面任何决定无关。**

## 三、语料使用面：搬来的东西有多少在被用

[语料] 18 张卡（19 张里 1 张无可扫内容）。扫的是**接口 HTML 的真实来源**——正则脚本的
替换串、脚本正文、开场白与备选开场白，**解析回原始字符串后再扫**（见下面的口径警告）。

| 库 | 用到的卡 | 打包体积 |
| --- | --- | --- |
| jQuery | **15 / 18** | 89 KB |
| Tailwind | **13 / 18** | 260 KB |
| lodash | 11 / 18 | 在 preset |
| zod | 10 / 18 | 在 preset |
| FontAwesome | 6 / 18 | 909 KB（含重复） |
| **Vue** | **3 / 18** | 109 KB |
| **jQuery UI** | **0 / 18** | **255 KB** |
| **touch-punch** | **0 / 18** | 1 KB |
| **VueRouter** | **0 / 18** | 在 preset |
| **YAML** | **0 / 18** | 在 preset |

### ⚠️ 两个数是我第一遍量错的，写出来因为错法可复现

第一版探针跑在 `JSON.stringify` 过的文本上，于是：

- **Tailwind 报 0，实际 13。**探针要求字面 `class="`，而 JSON 里是 `class=\"`。
  **一个坏探针给出的零和一个真的零长得一模一样。**
- **Vue 报 10，实际 3。**第一版探针把 `{{ ... }}` 算作 Vue 插值——**那是 SillyTavern
  的宏语法**，几乎每张卡都有。假阳性把一个 3/18 的库读成了 10/18。

第二版解析回原始字符串再扫，并把 Vue 的判据收紧到 `Vue` / `v-if=` / `v-for=` /
`createApp`。**上表是第二版的数。**

### FontAwesome 的字形面

[语料] 6 张卡合计用到 **258 个不同字形**（已剔除 `fa-solid` `fa-fw` `fa-spin` 这类
样式类）。FontAwesome 6 Free 全集约两千个，所以**用到的不足 13%**。

## 四、瘦身选项与破坏面

### A. 字体去重 —— 省 399,597 B（17.5%），**破坏面：零**

见 §一。同一份字节的重复副本。**先做，无条件。**

### B. 砍掉 jQuery UI + touch-punch —— 省 316,938 B（13.8%）

[语料] **零使用**，两个独立探针都零：方法调用（`.draggable(` `.resizable(`
`.sortable(` `.datepicker(` `.dialog(` …）和类名（`ui-widget` `ui-icon` `ui-state-`）。

**破坏面：语料内零命中，但无机制保证。**上游给楼层 frame 注入它
（[上游] `iframe/third_party_message.html:4-6`），所以一张调 `.draggable()` 的卡
**在 ST 能跑、在我们这儿会 `TypeError`**。

这与 `WINDOWING.md` 里「用户行零接口」那条边界同形。**同样的处理方式**：可以砍，
但要让失败有声音——frame 里留一个具名的存根，被调用时抛
「这张卡用了 jQuery UI，Iris 的楼层预设默认不含它」，而不是 `undefined is not a function`。
**具名拒绝把一个「卡坏了」变成一个可上报的事实。**

### C. FontAwesome 字体子集化 —— 至多再省约 350 KB，**不建议做**

258 个字形只占全集的不足 13%，子集化收益很大。**但破坏面是真实且不可预测的**：

- 语料驱动的子集把**当前 19 张卡的字形集固化成了产品约束**；第 20 张卡用第 259 个
  字形就中招。
- **失败形态最坏**：缺字形不报错，只是渲染成一个空方框或豆腐块。既不抛异常、
  也不进任何日志——`OBSERVABILITY.md` 里「没有声音的失败」的教科书例子。

**要做的前提是先有「缺字形时具名报告」的机制**，而那个机制本身比省下的 350 KB 贵。
**建议排在 A、B、D 之后，或者不做。**

### D. 按卡预判注入 —— 我们能做而上游做不了的那一类

**懒加载在这里是不成立的**：卡的接口 HTML 在 parse 时就用 `$`，而 `<script src>`
在 `<head>` 里是**解析时就绪**的。任何「用到再加载」都晚于第一次使用。
（这与 `srcdoc.ts` 里 context 必须内联的理由是同一条：**parse 时刻不等人**。）

**可行的边界是按卡预判**：宿主组装 srcdoc 时扫这张卡的接口 HTML，决定注入哪几个库。

- **为什么我们能做**：srcdoc 由宿主拼装，库从我们自己的源按内容哈希提供。
- **为什么上游做不了**：[上游] 它的 8 个 `<script src>` 是写死在
  `third_party_message.html` 里的 CDN 直连，**没有组装这一步**。

  这正是升级账本里那类分歧：**不是我们更聪明，是我们多了一个上游没有的接缝。**

**破坏面：预判错了 = parse 时 `$ is not defined`**，而 `frame-entry` 的 try/catch
是运行时的、来不及存在（`METHODS.md` 记过这个形状：解析期失败只能从外面看）。

所以预判必须**宁可多带**：探针命中就带，不确定就带。按 §三 的分布，
「带 jQuery + Tailwind + lodash + zod，按需加 Vue 和 FontAwesome」已经覆盖 18/18。

### E. 拆成两级预设

核心（jQuery + lodash + zod ≈ 覆盖 15/18）与可选（Vue / Tailwind / FontAwesome /
jQuery UI）分开成两个内容哈希文件。D 的实现形式之一，**收益相同、粒度更粗**——
好处是文件数少、缓存条目少；坏处是两级之间的取舍点要靠猜。

**在 D 有实测之前，E 不比 D 好。**

## 五、和上游比，我们已经在哪一侧

[上游] 楼层 frame 的库是 `third_party_message.html` 里 **8 条 CDN 直连
`<script src>` / `<link>`**（7 条走 `testingcf.jsdelivr.net`，Tailwind 走扩展本地副本）。

| | 上游 | 我们 |
| --- | --- | --- |
| 来源 | CDN 直连 | 自己的源，内容哈希 |
| 缓存 | 由 CDN 与浏览器决定 | 强缓存、内容哈希、可离线 |
| 首包 | 8 个请求，跨 3 个主机 | 1 个请求 |
| **能否按卡裁剪** | **不能**（写死在静态 HTML 里） | **能**（宿主组装 srcdoc） |
| 版本 | 无版本 CDN tag，随时漂移 | 精确 pin 到用户机器上装的那版 |

**「第一口 2.29 MB」是我们自己的问题，也因此是我们能自己修的问题。**上游那 8 个请求
的总量并不更小，只是被拆散在 CDN 上、由不知情的第三方决定缓存策略。

---

## 六、建议顺序

1. **A 字体去重** —— 省 17.5%，零破坏面，与其它决定无关。**先做。**
2. **B 砍 jQuery UI + touch-punch** —— 再省 13.8%，配一个具名存根让失败有声音。
3. **D 按卡预判注入** —— 结构性收益，且是升级账本上的一条真分歧。
4. **C 字体子集化** —— 不做，除非先有缺字形的报告机制。

A + B 合计省 **716,535 B ≈ 31.3%**，把 2.29 MB 降到约 **1.57 MB**，
且**没有任何一张语料卡会察觉**（A 是同字节，B 是零使用）。
