# 扩展系统设计裁定（总指挥，2026-09-12）

本文件是第三方扩展系统（E 系列）全部设计工作的宪法。任何设计文档、PoC、实现 PR
与本文件冲突时，以本文件为准；要推翻本文件的某条，先在本文件写推翻条件。

## 裁定一：扩展是 Cordis 节点，宿主侧 ONLY

- 第三方扩展 = **宿主侧 Cordis 插件**（cordis.yml 一行 + 一个 npm 包），不是前端组件、
  不是帧内脚本。卡脚本面（TH/ST 兼容）是**已被占用的扩展点**，归 compat 层管，
  扩展系统不开放它——那扇门后面是 171+ 成员的兼容承诺。
- **前端不做第三方加载**。shell 产物是构建期的；运行时往页面注入第三方 JS 等于把
  style-src-elem 那类边界全部重开。渲染层的可扩展点（如正文美化、模板执行开关的
  UI 挂载）通过**声明式的设置面贡献**实现（见裁定三），不是注入代码。

## 裁定二：能力面 = 受控的服务注册，不是任意 RPC

- 扩展能触达的能力 = 宿主通过 **ctx.provide** 显式暴露的 service 接口子集
  （storage 命名空间、事件订阅、生成管线钩子、设置面贡献），列进 `docs/EXTENSIONS.md`
  的稳定契约；契约外的 inject 拒绝。
- 生成管线钩子是第一公民（模板、美化类功能的服务端形态都挂这里），钩子签名
  版本化（`apiVersion`），破坏性变更走新钩子名不原地改。

## 裁定三：贡献 UI 的方式是声明，不是代码

- 扩展可向设置抽屉/阅读卡贡献**开关与简单控件**：扩展在包里声明
  `iris: { contributes: { settings: [...] } }`（标签、键、类型、默认值、token 类名），
  宿主渲染。控件类型白名单：toggle/choice/number/text。第一版**不做**自定义
  DOM/任意 React 组件贡献——那等于把前端插件化从后门放进来。

## 裁定四：信任模型 = 装机即宿主权限

- 扩展与宿主同进程、同权限（Node 进程边界内没有便宜的隔离）。因此：
  - **没有扩展市场、没有自动安装**。安装 = 用户自己 `pnpm add` + cordis.yml 加一行，
    与添加一个 provider 适配器同级的心智负担
  - 文档明写：「扩展是你机器上的特权代码」。扩展系统的价值在**边界清晰的钩子契约**，
    不在沙箱幻想
- 禁区（任何扩展不得触碰，宿主在 provide 时拒绝）：原始文件系统路径直读用户数据
  之外的位置、密钥明文读取（走 connection 服务得脱敏面）、绕过 host.lock 的第二写入路径

## 裁定五：先例

- 上游 ST 的扩展 = UI 插件（注入页面 JS）——**明确不学**，理由见裁定一
- Cordis 自身的 plugin 生态（@deepseek-ai/cordis-plugin-*）= 我们要的形态的既有证明，
  dsh 系列包就是榜样：一个包一个能力，cordis.yml 一行接入
- Iris 自己的 llm-openai-compat 行就是第一个"扩展"：换 provider 是配置不是代码

## 验收标准（E 系列完成线）

1. `docs/EXTENSIONS.md`：契约文档（能力面、钩子签名、贡献语法、禁区、生命周期）
2. 第一个一等扩展把**现有某能力搬出去**证明形态（候选：模板执行开关、cache-trace、
   正文美化的服务端钩子形态）——扩展包在仓库内、cordis.yml 一行、可注释掉整行即卸载
3. PoC 扩展从零接入的体验 ≤ cordis.yml 一行 + 一个 package.json
4. 全部既有纪律不回退（测试、双 tsc、rehearsal、md 引用）
