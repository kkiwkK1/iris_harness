# P0 试点用例 —— P3 兼容试台的验收剧本

日期：2026-09-13。性质：定义 RUNBOOK §1 第一版交付指标（“一个不修改上游代码的简单扩展完成安装、真实功能、停用和恢复”）在本试点的可观察判定。试点对象锁定为 `pilot-lock.md` §1 的 ST-Prompt-Template `f9a07da`。用例在 P3 完成执行；本文件只定义判定，不预设实现。

通用前置（所有用例）：

- 临时 profile + mock provider（RUNBOOK §11：先离线，不发真实模型请求）。
- 同一 profile 内旧 MVU 实现保持停用——模板扩展的 `setvar` 与 MVU 是两个变量写入路径，同开即违反“一个功能只能有一个活动实现”（RUNBOOK §1）。
- 判定读取的是宿主权威数据（`prompt.itemization`、`script.getVariables`、插件快照），不是兼容环境自己的日志。

## UC-1（无 UI）提示词模板在生成时展开

前置：扩展已安装并启用；一张测试卡的世界书条目含上游 README_CN 的例 2 原文：

```
<% if (getvar('好感度', { defaults: 0 }) > 50) { %>
你是我信赖的朋友。
<% } else { %>
我仍然对你保持警惕。
<% } %>
```

步骤与判定：

1. 设 `好感度` 为 70，`chat.send` 任意消息 → `prompt.itemization` 中该条目显示“你是我信赖的朋友。”，且**不含** `<%` 残留。
2. 设 `好感度` 为 10，再次生成 → 显示“我仍然对你保持警惕。”。
3. **停用**扩展 → 再次生成 → 模板原文原样进入提示词（不展开、不报错），聊天功能不中断。
4. **恢复启用** → 重复步骤 1 → 展开恢复，与步骤 1 逐字节一致。
5. 对照：同输入在本机 ST 1.18.0（`51ad27fb8` + 扩展 `f9a07da`）中的展开结果作为对照记录；角色数据只记录结构与哈希（RUNBOOK §11）。

反例（任一出现即失败）：展开结果双写变量；停用后仍有部分模板被处理；恢复启用后出现第二次初始化副作用（重复注入的系统消息）。

## UC-2（无 UI）回复内模板更新变量

前置：同 UC-1，模型回复（mock provider 返回固定文本）含上游例 3 形态：

```
<% setvar('好感度', getvar('好感度') + 10) -%>
你的善意我已收到。
```

步骤与判定：

1. 初始 `好感度` 0，收到回复 → `script.getVariables` 读到 10；消息楼层显示已清掉模板脚本的正文。
2. 再次生成 → 20（变量按次累加，跨轮持久）。
3. 停用扩展 → 生成一轮 mock 回复（仍含模板文本）→ 变量**不变**（仍为停用前值），原文进入楼层。
4. 恢复启用 → 生成 → 从停用前值继续累加，**不重放**停用期间文本（对齐 SYSTEM-PLUGINS.md 的 MVU 同族语义）。

反例：停用期间变量被写入；恢复后历史命令重放。

## UC-3（UI）扩展设置面板

前置：扩展启用；扩展自带 `settings.html` 与 i18n（`zh-cn`）。

步骤与判定：

1. Iris 设置页出现该扩展的面板（映射到标准设置插槽 `iris.settings.sections` 一族，不是全页面 ST 布局模拟）；界面语言为中文时面板文案为 `locales/zh-cn.json` 的译文。
2. 面板内改一项设置 → 刷新/重载宿主后仍生效（per-profile 存储）。
3. 停用扩展 → 面板消失，无残留 DOM/监听；卸载 → 数据按默认保留（删数据是独立动作，RUNBOOK §5）。
4. 键盘可达（SYSTEM-PLUGINS.md 验收要求）。

反例：面板查询逃逸出限定根节点（RUNBOOK §7 的“限定 jQuery 根节点”边界）；停用后面板残留可交互。
