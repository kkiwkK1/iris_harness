## 0. 先修正一个前提

任务单说「W6 正在修两条已知的，这十遍能告诉我们还有没有第三条」。**W6 已经落地**：app-service 台账 **§90**「第三批偶发红：`scoped-regex` 的清理 `EBUSY`，与 `variable-writers` 的墙钟屏障」，接在 §86（第二批：`chat-search`、`chat-integrity`）之后。也就是说，已知的四条偶发红**都已按「先确定性复现、再修原因」的方法关掉**。所以这十遍问的不是「还有没有第三条」，而是：

1. §86/§90 修的四条，在顺序负载下是不是真的一次不红；
2. 有没有**从未见过**的偶发红——这三周新加了约 1 000 个用例（今天 4 315 个），新用例里有没有带墙钟或临时目录的。

## 1. 量尺

- 命令：根目录 `npm test` 展开是 `node --test "packages/*/tests/**/*.test.ts" "apps/*/tests/**/*.test.ts"`。Node 24.13 默认按 CPU 数并行跑文件（本机 16 核）；顺序跑加 `--test-concurrency=1`。**顺序跑是为了把「并行抢资源」这个变量拿掉**——如果顺序还红，那是测试自身的问题；如果只在并行红，那是测试之间的干扰（共享端口、临时目录、墙钟）。
- 每遍留全文日志，不要只看尾巴。红的判定看 `✖` 行和最后的 `ℹ fail N`。
- 一遍多久：并行约 75 s；顺序估 3–5 分钟。十遍约一小时；开着别干别的（不要同时跑门禁、不要起宿主）。

## 2. 步骤

在你自己的树里，`main` 拉到 `5601082` 或之后，依赖装好（`pnpm install --frozen-lockfile --offline`；`apps/iris-web` 里 `npm install --offline && npm run build`——`no sandbox build in this checkout` 会让几条测试变 skip，那不算红但会污染计数，所以先 build）。

```
mkdir -p "$TEMP/suite-10"
for i in 01 02 03 04 05 06 07 08 09 10; do
  FORCE_COLOR=0 node --test --test-concurrency=1 "packages/*/tests/**/*.test.ts" "apps/*/tests/**/*.test.ts" > "$TEMP/suite-10/run-$i.log" 2>&1
  echo "run $i: $(grep -E '^ℹ (tests|pass|fail|skipped)' "$TEMP/suite-10/run-$i.log" | tr '\n' ' ')"
done
```

（PowerShell 的话用 `1..10 | % { ... }`，重定向一样。）每遍结束打印四个数。**十遍的 `tests` 数应完全相同**；不同就是有用例在条件性注册，先记下。

然后抽红：

```
grep -l "^ℹ fail [1-9]" "$TEMP/suite-10"/run-*.log
grep -h "^✖ " "$TEMP/suite-10"/run-*.log | sort | uniq -c | sort -rn
```

第二条给出「哪个用例红了几遍」。对每个红过的用例，去日志里抠断言信息（`✖` 下面缩进的 `AssertionError`/`Error` 段），红的原因比红的次数重要。

## 3. 再加两遍并行，作对照

顺序十遍之后，**并行再跑两遍**（就是裸 `npm test`），同样留日志。目的：如果某条只在并行红，说明是测试间干扰而不是测试自身——这决定它交给谁修（夹具屏障 vs 逻辑）。

`notes/TEST-STABILITY-2026-09-xx.md`，状态头「记录，测量于 <日期>，对象 main `<sha>`，机器 <CPU/内存一行>，顺序十遍 + 并行两遍」。三张表：

1. **十二遍总览**：遍号 · 模式 · tests · pass · fail · skipped · 时长。
2. **红的用例**：文件 · 用例名 · 顺序红几遍 / 并行红几遍 · 断言信息（原样一行）· 用例里有没有墙钟/临时目录/端口（看一眼源码，`setTimeout`、`mkdtemp`、`port: 0` 之外的固定端口、`Date.now`）· 是否在 §86/§90 点名的四条里。
3. **skip 的用例**（如果十遍里 skipped 数不为 0）：名字与 skip 原因——skip 也是一种「没量到」。

一句结论：四条已修的红了没有；新红几条；每条你怀疑的层（测试自身 / 测试间干扰 / 产品）。**不修**。

## 5. 边界

- 不改测试、不改超时、不加重试。看见 `EBUSY`/`EPERM` 之类 Windows 临时目录瞬态也只记。
- 跑的时候不要同时跑门禁、不起宿主、不装依赖（§90 那条 `EBUSY` 就是清理和别的进程抢文件）。
- 十遍中途别升级 Node、别切分支。
