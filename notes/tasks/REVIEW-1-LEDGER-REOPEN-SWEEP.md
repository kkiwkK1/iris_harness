## 2. 每一句怎么判

对每一段「What would overturn it」，回答三个问题，只写事实：

1. **条件是什么**——用一句话复述（例：「出现一张真实卡把玩家进度写进 message-scope 变量并跨楼读回」）。
2. **成立了吗**——三种答案，只能选一：
   - **成立**：指出证据——PR 号 / 合入 commit / 台账某节 / 语料里的某张卡（`notes/TEST-CARDS.md` 有族图与卡名）。
   - **未成立**：不写理由，写一句「截至 e668785 未见」即可。
   - **判不了**：条件依赖一次没人做过的测量（例如「有卡这么用」需要扫语料）。写清楚缺哪一步测量，**不要猜**。
3. **成立了的话，决定被推翻了没有**——推翻 ≠ 条件成立。有的条件成立后代码已经跟着改了（像 §76），有的成立了但代码还是老样子（那是一条待办）。分开写。

判断时以代码为准，不以文档为准：先 `git grep` 相关符号，再读那一处。台账里的 `path:line` 是当时的行号，只当线索。

## 3. 怎么记

**原文一个字不改。** 在该节末尾（下一个 `## ` 之前）追加一段，格式固定：

```
> 复查（2026-09-xx，e668785）：重开条件「……」已成立——证据 #101 / host §82。决定已随之改变（§82 记录）。
```
或
```
> 复查（2026-09-xx，e668785）：重开条件「……」已成立——证据 ……。决定**尚未**重看，见 REVIEW-1 清单第 N 条。
```
未成立的**不追加**（否则 180 句每句一行，台账会被复查行淹没）；只在清单里记一行。

清单文件：`notes/LEDGER-REOPEN-SWEEP-2026-09-xx.md`，状态头「记录」，一张表：台账 · 节号 · 条件复述 · 结论（成立/未成立/判不了）· 证据 · 是否已重看。表尾三个数：扫了几句、成立几句、其中几句还没重看——最后那个数就是这次巡检交给我的待办。
